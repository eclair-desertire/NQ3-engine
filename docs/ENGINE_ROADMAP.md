# План переработки движка

Цель — собственный движок соревновательного арена-шутера: от Quake остаются ощущение движения,
отзывчивость и надёжная сетевая модель, а всё остальное постепенно становится своим.

Связанные документы:
- [RENDERER_ROADMAP.md](RENDERER_ROADMAP.md) — графика (PBR, свет и тени, атмосфера);
- `vinitive/docs/STANDALONE.md` — замена ассетов OpenArena на свои.

## Принципы

1. **Игра работает после каждого шага.** Никаких «большого переписывания» с неработающей сборкой месяцами:
   подсистема заменяется, пока рядом живёт старая, затем старая удаляется.
2. **Ощущение движения неприкосновенно.** Физика (`bg_pmove`), предсказание на клиенте и детерминизм
   сервер/клиент проверяются тестами при каждом изменении.
3. **Задержка — главный показатель.** Любая новая функция меряется по FPS, времени кадра и задержке ввода.
   У каждой «тяжёлой» возможности есть выключатель.
4. **Проверяемость.** Автотесты (физика, сеть, загрузка карт), скриншоты «до/после», сборка на CI.
5. **Лицензии.** Код движка остаётся GPL v2. Сторонние библиотеки — только совместимые
   (MIT, BSD, zlib, ISC, LGPL), ассеты — свои или CC0.

## Направления

### 1. Идентичность и платформа
- Собственная база игры `vinitive` вместо `baseq3`/`baseoa`; свои папки настроек и сохранений.
- Удаление наследия: CD-ключ, Team Arena (`missionpack`), авторизация id Software, Steam-пути Quake 3.
- Сборка под Linux (SDL), затем установщик/лаунчер с автообновлением.
- **CI на GitHub Actions:** сборка Windows/Linux, тест физики, «дымовой» тест сервера (карта грузится,
  бот/клиент подключается), сравнение скриншотов.

### 2. Сеть и соревновательная часть
Модель снапшотов Quake 3 (сервер шлёт дельты состояния, клиент предсказывает себя) — отличная основа,
её сохраняем и развиваем:
- **Частота обновлений.** `sv_fps` по умолчанию 20 — для современного киберспорта мало. Переход на 60–125 тиков,
  с проверкой трафика и нагрузки; отправка снапшотов не реже частоты ввода.
- **Лаг-компенсация.** Сервер «отматывает» положения игроков на момент выстрела клиента для мгновенного
  оружия (рейлган, молния, пулемёт) — честные попадания при пинге 50–100 мс.
- **Точное время ввода.** Временные метки команд внутри кадра, чтобы стрельба и прыжки не зависели от FPS.
- **Безопасность.** Шифрование и аутентификация соединения (libsodium), защита от подмены пакетов,
  серверная проверка ввода; затем античит (серверные эвристики, проверка целостности клиента).
- **Свой мастер-сервер** (на основе открытого dpmaster или с нуля), затем аккаунты, рейтинг, матчмейкинг.
- **Демо и наблюдатели:** запись матчей, свободная камера, инструменты трансляции (HUD для зрителей).

### 3. Архитектура игрового кода
- **Отказ от QVM.** Виртуальная машина Quake 3 нужна была для безопасных модов на C 1999 года.
  Игра собирается нативно; в будущем моды — через встроенный скриптовый язык (например, Lua) с песочницей.
- **Данные вместо кода.** Оружие, предметы, режимы и параметры физики описываются в файлах конфигурации,
  а не жёстко в C — балансировать можно без пересборки.
- **Чистые границы модулей.** Общий код сервера и клиента игры (`bg_*`), игровые системы как отдельные модули
  (оружие, предметы, режимы, PvE).
- **Режимы:** дуэль, TDM, CTF, PvE-волны; правила режима — модуль, а не ветки `if` по всему коду.

### 4. Интерфейс и текст
- **Новая система интерфейса** вместо `q3_ui`/`ui` (42 тыс. строк): компоновка, анимации, стили,
  редактируемый HUD. Главное меню и HUD уже переделаны в новом стиле — это прототип.
- **TrueType-шрифты во время игры (FreeType)** вместо запечённых атласов и **UTF-8** вместо CP1251:
  любые языки, чёткий текст при любом масштабе.
- Настройки с понятными пресетами, переназначение клавиш, локализация (основа уже есть).

### 5. Звук
- Замена микшера Quake 3 (`snd_*`) на **OpenAL Soft** или собственный микшер с **HRTF**: в соревновательном
  шутере направление шагов и выстрелов — игровая информация.
- Зоны реверберации, окклюзия звука стенами, приоритеты (свои шаги и выстрелы врага не теряются в шуме).
- Форматы: Ogg/Opus.

### 6. Ввод и отзывчивость
- Сырой ввод мыши с высокой частотой опроса, отделение частоты ввода от частоты кадров.
- Режим минимальной задержки: управление очередью кадров, точный лимитер FPS, frame pacing.
- Поддержка мониторов 240–500 Гц, измерение задержки «клик → вспышка».

### 7. Контент и форматы
- **Карты:** формат BSP Quake 3 и q3map2 остаются на ближайшее время (отлаженные инструменты, быстрые
  коллизии и видимость). Расширения: HDR-лайтмапы, пробы освещения, детальная геометрия из Blender.
- **Модели:** MD3 для оружия и предметов; **IQM со скелетной анимацией** для игроков (смешивание анимаций,
  ragdoll), переписывание системы анимации в `cgame`.
- **Текстуры:** сжатые форматы GPU (BC/KTX2) и PBR-материалы.
- **Конвейер:** Blender → скрипты → игра (уже работает для оружия), импорт glTF.

### 8. ИИ и PvE
- **Навмеш (Recast/Detour, лицензия zlib)** вместо AAS из `botlib`: строится автоматически из геометрии карты,
  поддерживает прыжки и джамп-пады.
- Противники для PvE (поведенческие деревья), боты для тренировки и заполнения серверов.

### 9. Качество и инструменты
- Профилировщик кадра (CPU/GPU), отчёты о падениях, журналы.
- Автоматические матчи ботов для проверки стабильности сервера.
- Тестовые сцены рендерера и сравнение скриншотов на CI.

## Этапы

Сроки ориентировочные, при постоянной работе; направления идут параллельно, где это возможно.

| Этап | Содержание | Ориентир |
|---|---|---|
| **M0 — Основа** (сделано) | Форк, CPM-физика, новый UI, русский, HDR и тонмаппинг, свой протокол, первая карта и оружие | — |
| **M1 — Самостоятельная альфа** | Своя база `vinitive`, никаких ассетов OpenArena: персонаж в стиле Tron, базовый набор оружия, 2–3 карты, звуки, меню; CI | 1–2 месяца |
| **M2 — Соревновательное ядро** | 60–125 тиков, лаг-компенсация, шифрование, свой мастер-сервер, дуэль/TDM, наблюдатели и демо, новый звук с HRTF | 2–3 месяца |
| **M3 — Современная картинка** | Этапы 2–4 рендерера: PBR, тени, SSAO, объёмный туман (параллельно с M2) | 2–4 месяца |
| **M4 — PvE и контент** | Навмеш, ИИ противников, режим волн, больше карт и оружия | 2–3 месяца |
| **M5 — Глубокая переработка** | Новая система UI вместо `q3_ui`, UTF-8 и FreeType, отказ от QVM, данные вместо кода, IQM-анимации игроков | 3+ месяца |

## Ближайшие шаги
1. **Персонаж в стиле Tron** — самый большой блок M1 и самый заметный.
2. **CI** — пока изменений мало, дешевле всего настроить сейчас.
3. **Своя база игры** и удаление наследия (CD-ключ, Team Arena) — небольшой шаг, заметно упрощает код.
4. Затем — оружие, звуки и меню по плану `STANDALONE.md`, параллельно этапы рендерера.
